Preset 作为能力包#

Preset 定义的是 “以什么能力运行”: 模型与指令、browser、memory、skills、MCP servers、plugins、subagents、container mode 和可见性策略都属于同一个能力包.

Poco 把 preset 当作可复用、可迁移、可绑定的配置单元. 它可以驱动一次临时执行, 也可以绑到 server agent identity. 它不携带某个 Agent 的私有长期状态.

Preset 展开成什么#

下图是 preset 在运行前展开的几样东西. 米色是配置和身份, 紫色是能力开关落到运行契约上的结果. 指向私有状态的虚线表示: identity 拥有长期状态, preset 不包含它.

Identity 负责谁在协作, preset 负责它具备哪些能力. Preset 可以被 identity 引用. 一个 Agent 可以换能力配置. 同一份能力包也可以被多个身份复用, 而不会复制私有记忆.

能力开关影响三层#

一个能力开关通常同时影响三层.

层影响
Runtime permission运行时是否允许访问 browser、memory、文件、MCP 或某类工具.
Tool injectionExecutor 是否注入对应的内置工具或外部工具服务.
Behavior contractPrompt 里是否说明该能力的使用边界和失败条件.

Channel runtime tools 是运行契约的一部分. Agent 如果能读取频道消息或创建 channel task, 必须同时具备 scope、工具注入和行为提示.

从 preset 到 runtime#

一次执行开始前, Backend 把 preset 解析进 run snapshot. Executor Manager 根据 snapshot 准备 workspace、挂载、工具配置和容器策略. Executor 再根据同一份契约注入工具、构造提示、启动 SDK client, 并把能力边界告诉 Agent.

Preset 因此决定运行时能看到什么、能调用什么、能写哪里, 以及失败时系统怎样解释 Agent 的行为. 能力配置如果只留在界面上, Agent 可能以为自己能做某事, 实际运行时却没有对应权限或工具.

Preset 与 identity 的迁移边界#

Preset 适合复制和迁移, 因为它描述的是能力组合. 一个团队可以把 “代码审查 Agent” 的 preset 复制到另一个 server, 或用同一个 preset 创建多个不同 handle 的 Agent.

Private state 不随 preset 复制. 长期 memory、active context、task state 和协作偏好属于 identity. 复制 preset 如果连带复制这些内容, 就等于复制某个 Agent 的历史, 隐私和语义都会混.

四组内容#

抽象用途
基础说明名称、描述、instructions.
运行策略container mode, 是否启用 browser 和 memory.
工具组合skill、MCP server、plugin、subagent 引用.
可见性私有、团队可用, 以及从哪个 preset fork.

运行时, Backend 把 preset 解析进 run snapshot, Executor 根据 snapshot 注入工具和提示. Preset 不需要知道当前频道消息, 也不需要知道 Agent private state 的内容.

取舍#

方案问题Poco 的选择
Preset 只是 prompt 模板无法表达工具、权限、运行策略和迁移.不采用.
Preset 包含长期记忆复用时泄露私有上下文, 身份和配置耦在一起.不采用.
Preset 作为能力包可复用、可迁移、可审计, 但要明确它怎样映射成运行契约.采用.

Preset 把 “如何运行” 做成稳定配置. “这个 Agent 过去经历了什么” 留在 identity 的私有状态里.

文件树与浏览器预览的可观测性设计#

Agent 说 “我已经完成修改并验证过页面”, 并不等于系统已经有可信证据. 用户需要看到哪些文件被产出、哪些成果被发布、哪些内容属于私有状态, 以及浏览器或页面状态能不能支撑最终回答.

Poco 的可观测性不只看最终文本. workspace output、published artifacts、private state、local mount 和 browser preview 分开展示. 用户能检查结果, 同时系统不会把所有运行时文件都变成公共材料.

文件落在哪一侧#

下图把一次工具执行产生的材料分成两侧. 绿色底是可以拿来核对的证据, 粉色底是受限材料. 私有状态和本地挂载可以给授权的人看, 不进入频道公共树.

Workspace output 是一次运行的结果. Published artifact 是频道共享成果. Private state 是 Agent 的长期记忆. Local mount 是用户授权给当前 session 的真实目录. 界面可以让用户检查它们, 但不能合成一个公共文件树.

浏览器预览回答什么#

浏览器预览回答一个具体问题: Agent 的说法能不能被运行中的页面或交互状态支撑. 它适合检查本地页面、表单、控制台、截图或自动化验证结果.

它不替代测试, 也不把所有 browser 记录刷进主消息流. 它放在执行详情里: 用户需要验证时打开, 默认不占频道对话.

从工具执行到可检查证据#

Agent 调用文件、shell 或浏览器工具之后, 证据链分成三步:

  • 系统记录过程事实, 包括工具输入、工具输出、错误、耗时和状态补丁.
  • Workspace export 把可保留的文件产物整理成 manifest.
  • Backend 根据边界判断哪些能成为 published artifacts, 哪些只能留在 private state 或 session 证据里.

浏览器预览也在这条证据链上. 它不证明任务一定正确, 但能让用户看到 Agent 是否打开过目标页面、是否观察到预期状态、是否有和最终回答一致的运行结果. 最终文本、文件树和浏览器预览互相印证.

共享成果和私有状态的读者不同#

频道共享成果树和 Agent private state 都可以出现在文件树里, 面向的读者不同. Shared artifacts 面向同频道成员和 Agent. Private state 面向 owner 或受控的历史检查. Local mount 受 session 授权限制.

用户为了看一份方案文档, 不应因此看到 Agent 的长期 memory 或本地挂载目录.

三类证据#

证据核心作用
Workspace output按 session 展示导出文件和 manifest.
Published artifacts按 channel 展示共享成果, 并支持只读预览.
Browser preview按 run 展示当前页面、截图或 trace 摘要.

Private state 不自动进入共享成果树. Local mount 不因为一次执行被频道成员继承.

取舍#

方案问题Poco 的选择
只展示最终答案用户无法确认文件和页面是否真的对得上.不采用.
暴露所有运行时文件私有状态和本地授权边界容易泄露.不采用.
按边界展示文件树和预览证据可以检查, 同时不打破权限边界.采用.

文件树和浏览器预览让 Agent 的过程和结果可以被检查、复用和追责.

  • OpenTelemetry: What is observability?: 最终结果之外为什么还需要过程证据.

  • GitHub Actions artifacts: 运行产物怎样被保存、展示和复用.

执行事件状态机与回放#

长任务不能只保存最终结果. Agent 运行中会经历排队、领取、准备、执行、工具调用、文件变化、失败、取消和完成. 系统如果只在最后保存一条 assistant message, 用户无法判断中间发生了什么, 恢复和排查也缺少依据.

Poco 用状态机表示 run 的当前阶段, 用事件和过程表记录发生过什么. 当前状态服务列表和调度. 过程事实服务回放、审计和执行详情.

Run 状态机#

下图是 run 的当前阶段. 黄色是还没进入执行的调度状态, 橙色是正在准备或运行, 绿色是成功结束, 粉色是失败. claimed 租约超时后回到 queued, 这次领取作废, 任务仍可被再次领取.

状态机只回答四件事: run 当前能否被 claim, 是否正在运行, 是否已经结束, 是否需要取消或重试. 过程细节不塞进状态字段, 否则查询和回放都会变重.

事件流记录发生过什么#

模型消息、tool use、tool result、todo 进度、当前步骤、workspace export 和错误信息都属于过程事实. 下图把它们和当前状态分开: 当前状态给调度用, 过程事实进入回放.

这些记录被聚合后可以更新当前状态, 也可以完整展示给用户, 或用于审计.

当前状态和历史事实分开存放#

Run 的当前状态会被频繁查询. 列表要知道它是否还在 running. 调度器要知道它是否还能 claim. 取消按钮要知道是否能生效. 这个状态应该小、稳定、容易索引.

历史事实用来解释过程: Agent 为什么给出这个回答, 哪个工具失败了, 哪个文件被导出, 哪个 todo 已完成. 它们通常更大、更细, 适合按 session 或 run 展开. 两类信息混在一个字段里, 调度查询会拖着巨大的过程数据, 回放也缺少结构化依据.

频道里的执行投影#

频道里触发 Agent 后, 用户需要立刻知道它开始工作了. 主消息流不应该变成完整的 execution transcript. Poco 在频道里创建 execution placeholder, 显示状态、当前步骤和简要进度. 点击后进入 execution drawer, 查看完整 session.

  • 主频道 保持多人协作时的可读性.
  • 执行详情 按 session 回放, 需要时可以从频道里的占位打开.

Artifact 与状态回放#

执行完成后, workspace export 可以同步成 published artifacts. 回放视图除了最终文字, 还展示工具调用、文件变化、browser evidence 和 artifact 的发布关系.

某个 callback 如果重复、延迟, 或来自过期 run, Backend 根据 run、session 关系和当前状态决定是否应用. 执行面的不稳定因此较少直接改写用户看见的事实.

三层记录#

抽象用途
Current state列表、调度、取消和终态判断.
Event history消息、工具、状态补丁、workspace export 等过程事实.
User projection频道 placeholder、execution drawer、文件树和回放视图.

这三层不必落在同一张表里, 但必须能通过 run 和 session 关联. Current state 让系统知道现在怎么办. Event history 解释发生过什么. User projection 让人在合适的信息密度下查看过程.

取舍#

方案问题Poco 的选择
只靠最终 callback过程丢失, 失败后难恢复和审计.不采用.
把完整执行 transcript 刷进频道主流频道很快难以阅读.不采用.
状态和事件混在一起当前阶段和过程历史难以分别查询.不采用.
状态机 + 事件流 + 执行抽屉当前状态清楚, 过程可回放, 频道仍可读.采用.

执行回放把 Agent 的过程收成系统事实的一部分.
